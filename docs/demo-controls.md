# Private demo controls

These opt-in controls are development work for private testing, not authorization to expose this deployment publicly. Existing accounts and the default installation retain their original behavior. Apply deployment changes only in a maintenance window; never test against an active workspace.

## Implemented foundation

For the first-time visitor pilot, enable `MONAILABEL_DEMO_SELF_REGISTER=1` together with `MONAILABEL_DEMO_CACHE_ONLY=1` and `MONAILABEL_DEMO_TRAINING_PREVIEW=1`. The signed-out page offers **Create demo account**, password confirmation, and a separate **Sign in** option for existing accounts. Registration uses `POST /api/auth/register-demo` and is restricted to requests arriving over the private loopback access path; this is not a public registration deployment. The initial administrator must already exist. Visitors choose a new username (3–40 letters, numbers, dots, underscores or hyphens) and a password of 12–256 characters. No email or paid service is required.

Registration atomically creates a non-administrator account, a distinct **My demo** project, project-scoped local model metadata, a fixed lease and a sign-in session. `MONAILABEL_DEMO_MINUTES` selects 60 minutes (default) or 120 minutes for new self-registrations; changing it does not extend existing visits. Registration does not copy another user's annotations or download data/model weights. The welcome panel's **Load one sample CT** button explicitly imports one cached Spleen CT, then opens Datasets; visitors can launch OHIF or Slicer there. The cache must already be prepared. A new project is an application-level access boundary, not an operating-system/container sandbox.

`MONAILABEL_DEMO_CAPACITY` defaults to two admitted visits (configurable from one to eight). This is a conservative trial setting, not a measured hardware capacity. A transaction serializes slot reservation with account creation, and rejects a full demo with `429`, a retry hint and `Retry-After`, without creating a partial account. Logging out does not free a reservation or reset its clock. Expired accounts with unfinished project jobs or browser desktops continue occupying a slot. Password hashing for signup is serialized, and registration allows at most ten attempts per minute per server process. There is also a safety ceiling of 1,000 retained demo accounts; these controls are not comprehensive public abuse prevention. Normal administrator-created accounts are not visitor reservations.

Admission, annotation workers and browser-desktop slots are separate limits. Raising admission does not add inference workers or desktop slots: extra annotation jobs queue, while desktop launches can be refused when their separate limit is reached. Measure fresh inference separately from prepared-result reuse, and include host RAM, per-GPU memory, coordinator latency and viewer memory before changing these limits. A successful trial at a given concurrency establishes a tested setting, not the machine's maximum capacity.

For a single server with multiple GPUs, the optional `MONAILABEL_DEMO_GPU_DEVICES` setting lists distinct physical CUDA device selectors, for example `0,1`. When `CUDA_VISIBLE_DEVICES` is also set, the selected entries must be included in that visibility list. Timed visitor inference workers lease one selected GPU at a time; only the new child process receives the narrowed visibility, so adapters using `cuda:0` see their assigned physical device without changing the threaded server's environment. Extra work waits in the existing bounded job queue. CPU-only frame extraction does not claim a GPU. Cancellation is checked while waiting, and the lease is returned after worker cleanup. Without this opt-in, existing device behavior is unchanged.

This is a process-local visitor-worker pool, not a cluster scheduler or a GPU-memory quota. It does not coordinate administrator in-process inference, another server, or unrelated CUDA programs. Keep those workloads off the reserved devices during a visitor pilot. Worker count, desktop caps, host RAM and per-model memory still need independent limits and testing. These environment settings are read by the server process; changing deployment configuration requires draining sessions and a normal restart, not starting a second server on the same workspace.

Administrators can still open **Team & roles → Create demo visitor**, choose a username and password, and select one or two hours. The equivalent API is `POST /api/auth/demo-users` with `username`, `password`, and `minutes` (60 by default, or 120). These invited accounts start their reservation at first sign-in and always check capacity, independently of the self-registration flag. For an invite-only pilot, leave `MONAILABEL_DEMO_SELF_REGISTER` unset or set it to `0`; the signup API refuses account creation and the signed-out page hides signup, without disabling invitation admission. Reconnecting an already-admitted visitor does not reserve a second slot. Invited accounts are not automatically assigned to the administrator's projects. Use a secure client that does not put passwords in shell history or logs. Do not convert an administrator account into a visitor.

## Login abuse limits

Password sign-in checks a 60-second sliding window before hashing: at most 10 attempts per normalized username, 30 per client address, and 120 globally, with at most four simultaneous verifications. Attempts include successful logins and nonexistent accounts; a success does not erase the limit. Rejected attempts return `429` with `Retry-After`, and never allocate new rate-limit buckets or perform password hashing. The API uses its transport client address, not a client-supplied `X-Forwarded-For` header. A reverse proxy must forward addresses only through explicitly trusted proxy configuration. Completed administrator setup also rejects further setup requests before hashing.

The windows are bounded, in-memory state for the application's single server process and reset at restart. They are not permanent account locks, multi-process coordination, or protection against network-level denial of service. A shared proxy address conservatively shares its source limit unless trusted forwarding is configured. Deployment still needs edge request/body limits and private administrator access. These sign-in controls do not restrict authenticated annotation work.

## Request and transport limits

Enable `MONAILABEL_DEMO_HTTP_LIMITS=1` for the staging/private pilot. The application dispatches at most eight concurrent HTTP requests and accepts sixteen WebSocket connections. Up to sixteen additional HTTP requests may wait for a handler slot for at most five seconds; a full or timed-out queue returns `429`. Waiting requests are not read or spooled by the application. This bounded queue accommodates parallel viewer-module downloads without increasing active upload or handler capacity. HTTP bodies are checked before JSON parsing or route dispatch, including chunked bodies: 128 MiB generally, 16 KiB for authentication endpoints, and thirty seconds total to receive a body. Temporary request spools close on success, disconnect, cancellation and handler failure. Long-running response streams keep their request slot.

Authenticated HTTP calls share token buckets per account, across cookies and bearer sessions: five writes/second with a burst of sixty, and thirty GET/HEAD requests/second with a burst of 256. Viewer startup loads many authenticated modules; its read burst does not consume the write allowance. A depleted bucket returns `429` and `Retry-After`; failed retries do not postpone recovery or consume another account's allowance. The map holds at most 1,024 buckets and prunes fully refilled inactive buckets. These counters reset at process restart. They limit request frequency, not the cost of one model operation.

The launcher uses `wsproto` with compression disabled and a 16 MiB message limit, including fragmented messages, and enables a Uvicorn concurrency limit of 64 with this flag. Custom ASGI launchers must reproduce these transport settings; an application-level message check runs too late to limit transport reassembly. The tested Uvicorn version is also the server package's minimum dependency. See [HTTPS preparation](https-deployment.md) for the independent loopback proxy controls and multi-tab validation.

## Visitor capabilities

Every account with a demo lease has restricted backend capabilities, whether invited or self-registered, and independently of the public-signup, cache-only and lifecycle switches. Visitors cannot upload arbitrary images/videos/reference datasets, add provider credentials, register models, change model providers, discover hosted catalogs, use arbitrary hosted annotation, or connect/import from external DICOM servers. The underlying services enforce these restrictions for HTTP routes, assistant tools and jobs; hiding a UI control is not the boundary. Existing project roles still apply, and ordinary non-demo accounts retain their existing capabilities. The configured workspace conversation assistant is separate from hosted annotation; use the host's prepared local coordinator for an offline pilot. The separate `MONAILABEL_DEMO_GPT=1` opt-in with a server-side OpenAI key permits the two fixed GPT annotation presets described in [Prepared visitor examples](demo-examples.md). It covers every registered visitor with active project access, not just named developers, and does not impose a spending budget.

Visitors can import only verified cached dataset templates, with at most five samples per import. A missing or changed cache fails without downloading, both before queue admission and in the worker. Only server-controlled template jobs and the fixed synthetic demo enter the actor/project-bound import context; clients cannot supply a bypass flag. Synthetic fixtures are not patient data. Normal viewer drafts, annotation submissions and reviews on accessible prepared assets remain supported. A five-sample per-request cap is not a cumulative disk quota.

Visitor model listings omit hosted providers other than the explicitly enabled fixed GPT choices, and local models whose required cache files, installed framework modules or configured worker interpreter are missing. Explicit unprepared model IDs fail before annotation job admission. Reading local presets does not discover hosted catalogs or replace their provider configuration. The catalog performs lightweight presence/size checks, not a full model health test. Inference loaders verify pinned checkpoint checksums on use and refuse missing or changed files without creating download locks, downloading or repairing caches. The prepared-only capability follows HTTP, assistant and background-job execution independently of the lifecycle switch, and is inherited by fresh inference workers. A removed cache after preflight cannot trigger a download. Live training and hosted-only classification/ROI jobs are rejected before queue insertion even when the optional expiry sweeper is disabled.

For visitor nnInteractive, the host must provide `MONAILABEL_NNINTERACTIVE_PYTHON` as an absolute path to an already installed, dedicated Python environment. That interpreter runs the worker directly with user-site/PYTHONPATH isolation; no `uv` or package installer is invoked. The worker verifies `nninteractive==2.6.0`, `nnunetv2==2.8.1` and `torch==2.11.0` before inference. A missing environment or mismatched versions fail without automatic installation. Keep this environment separate from the server's MONAI/TotalSegmentator environment. Ordinary operator use retains its existing pinned `uv` preparation path when no prepared interpreter is configured. The host may set `MONAILABEL_PREPARED_MODELS_ONLY=1` to enforce prepared-only weight/runtime use for all accounts. Model caches and runtime paths are trusted host configuration, not client-supplied settings; protect them from visitor writes. These application checks are not an operating-system network sandbox, a cumulative disk quota, or a guarantee that a particular model fits available GPU memory.

Leased visitors always open Slicer/QuPath in managed browser desktops, even through localhost and even when the lifecycle sweeper is disabled. Their launch checks require an existing desktop image, noVNC client and native viewer executable before queue admission, and check again in the worker before issuing a desktop credential. Visitor startup cannot build images or download viewers; container startup also refuses implicit image pulls. OHIF requires a current cached extension build or an explicit host-prepared `MONAILABEL_OHIF_DIST`. Its configured distribution remains a host trust decision, not an integrity attestation. Missing resources are refused without installing them. Managed CVAT must already have its pinned service/UI and service credentials prepared by the host; visitors cannot start, repair or install shared CVAT services, or use externally managed CVAT. These checks do not replace resource quotas or native-runtime vulnerability updates.

## Cumulative artifact storage

Content-addressed workspace artifacts have durable byte and object accounting. Each leased visitor has an 8 GiB / 10,000-object allowance, independently of the public-signup and lifecycle switches. Defaults are controlled by `MONAILABEL_DEMO_ARTIFACT_BYTES` and `MONAILABEL_DEMO_ARTIFACT_OBJECTS`. Arrays include their actual NumPy encoding/header, and JSON, streamed files, masks and checkpoint blobs use the same reservation path. Limits must be positive integers; invalid settings fail closed.

Visitor writes also observe workspace-wide limits of 64 GiB, 200,000 physical objects and 200,000 visitor/object claims (`MONAILABEL_DEMO_ARTIFACT_TOTAL_BYTES`, `MONAILABEL_DEMO_ARTIFACT_TOTAL_OBJECTS`, `MONAILABEL_DEMO_ARTIFACT_TOTAL_CLAIMS`). The physical total includes existing operator artifacts. A shared blob takes physical space once but is charged once to each visitor who saves it; repeating the same save does not spend that visitor's allowance twice. Set `MONAILABEL_DEMO_STORAGE_LIMITS=1` to apply the global limits to ordinary/operator writes as well. Ordinary accounts otherwise retain their existing write behavior and can exceed the visitor-facing global ceiling.

A separate SQLite ledger and cross-process file lock reserve the exact encoded size before creating an artifact spool. New writes also require 1 GiB of filesystem headroom, configurable with `MONAILABEL_DEMO_STORAGE_FREE_BYTES`; this is a check, not a filesystem reservation against unrelated processes. Full budgets return `507` with `storage_quota_exceeded`; storage contention returns `429`. Rejected saves do not delete previous revisions or advance their records. The writer verifies streamed content before atomically publishing it. An interrupted write stays charged until exclusive server startup removes its own ledger-tracked partial file or recognizes its completed artifact. Startup accounts for pre-existing artifacts and reconstructs visitor claims from retained project records and nested artifact manifests. Reducing a limit below existing usage preserves existing data and refuses additional growth; it does not automatically remove work. Retained orphan blobs remain charged until ordinary startup garbage collection actually removes them.

Reconstructing previously untracked claims also obeys the claim-count limit. If existing project data would need more claims, startup stops with an operator error and rolls back the incomplete accounting; it does not delete saved work or start with missing visitor charges. The host must approve a suitable claim limit before restarting that workspace.

These limits cover the application's immutable artifact store, not the entire workspace or host disk. Metadata and application-controlled temporary spools have separate limits below. Provider/decoder scratch, external CVAT data, native `/session` and `/connection` mounts, logs and backups require separate limits or operator retention. Do not replace durable native mounts with volatile storage as a shortcut: that would risk saved drafts. A host-level quota and recovery plan remains a deployment prerequisite.

## Cumulative metadata allocation

Leased visitors also have a persisted 64 MiB / 20,000-record metadata allocation (`MONAILABEL_DEMO_METADATA_BYTES`, `MONAILABEL_DEMO_METADATA_RECORDS`), independently of signup/lifecycle flags. This includes application records, conversation growth, tool receipts, login sessions and background-job publication. Invitation/signup creation checks its initial account/project allocation in the same transaction, so a full allowance cannot leave a partial account. Server-record ownership attributes authentication and job-log writes even when they run outside an HTTP actor context.

Visitor mutations also observe global ceilings of 512 MiB, 200,000 record identities and 400,000 visitor/record claims (`MONAILABEL_DEMO_METADATA_TOTAL_BYTES`, `MONAILABEL_DEMO_METADATA_TOTAL_RECORDS`, `MONAILABEL_DEMO_METADATA_TOTAL_CLAIMS`). Global accounting includes operator-created records and archived feedback. `MONAILABEL_DEMO_STORAGE_LIMITS=1` applies the global mutation ceilings to ordinary/operator writes too; without it, operator preparation can exceed them. Application record writes check and publish within the same SQLite writer transaction. Rejected growth returns the same `507 storage_quota_exceeded` response as artifact exhaustion, and transaction rollback preserves prior revisions and decisions. Internal SQL triggers maintain accounting, including trusted maintenance writes; application mutations must use `Session.insert`/`update` for admission checks rather than issue raw INSERT/UPDATE statements.

Allocation uses the UTF-8 serialized record size plus 512 bytes of lifecycle headroom at creation; jobs reserve 64 KiB instead. Updates first consume that headroom, then require additional allowance. Progress/error text is bounded, and job-result publication carries the submitting visitor's identity. If an additional job log does not fit, that new log is omitted without changing earlier entries or sequence numbers; cancellation/failure/interruption still uses the existing job's reserved allocation. This is not a guarantee against an unrelated process filling the physical disk.

Metadata accounting is deliberately cumulative: each record and each visitor claim keeps its highest allocated size, including after deletion or an explicit demo reset. Shrinking/recreating/deleting records does not refund this allowance or permit unbounded tombstone, change-counter and accounting growth. A successful reset archives feedback and retains the allocation history; if enabled global limits cannot fit its archive, the entire reset rolls back. The host must plan capacity/retention for the intended pilot and approve any later limit increase or offline archival migration. Normal restart does not clear accounting. Initial migration preserves existing records and reconstructs visitor/project claims; an insufficient claim-count limit stops migration without deleting user data.

These are logical application allocation bounds, not exact SQLite file sizes. Page/index/WAL overhead, filesystem free space, native viewer mounts and temporary/external files still require a host-level disk budget. Do not truncate the database or delete quota tables to make a full deployment appear ready.

## Application temporary spools

Leased visitors' dataset exports reserve a 2 GiB temporary allowance before writing (`MONAILABEL_DEMO_EXPORT_TEMP_BYTES`). The ZIP and any generated image/mask files share this allowance; streamed writes check their aggregate extents before growth. ZIP header rewrites do not spend space twice. NumPy and image encoders use the checked writer rather than bypassing it through a raw file descriptor. Generated intermediates are removed after their archive member is complete. The finished archive must also pass the permanent artifact quota before publication. A refused export fails its job without changing saved annotations or offering an incomplete download; a fresh export can be retried after capacity is available.

Timed local inference reserves 4 GiB for its serialized input and result together (`MONAILABEL_DEMO_COMPUTE_TEMP_BYTES`). Input overflow is refused before spawning a worker; the child bounds its result and the parent checks its size before deserializing it. Only server-constructed arguments/results use these private pickle files; no request supplies a pickle, callable or path. Unused raw child stdout/stderr is discarded instead of accumulating an unbounded `worker.log`; structured domain errors remain in the job error path. The fresh Linux worker and its descendants inherit a hard 2 GiB per-file limit (`MONAILABEL_DEMO_COMPUTE_FILE_BYTES`) and disabled core dumps. A stricter pre-existing process limit is preserved. The shared server's process limits are not changed.

Reservations share a separate SQLite ledger under `temporary-spools/`. Defaults allow 8 GiB / 32 reserved spools globally and 4 GiB / four spools per visitor (`MONAILABEL_DEMO_TEMP_TOTAL_BYTES`, `MONAILABEL_DEMO_TEMP_TOTAL_SPOOLS`, `MONAILABEL_DEMO_TEMP_VISITOR_BYTES`, `MONAILABEL_DEMO_TEMP_VISITOR_SPOOLS`). Whole allowances are reserved, not just current file sizes: with defaults a visitor can hold two exports or one timed inference reservation. These are independent of queue admission and worker counts. Reservation checks are transactional across processes and also check the configured free-space headroom. Limit settings must be positive integers. Leased export jobs are identified from their stored owner even without a current request actor or lifecycle flag. `MONAILABEL_DEMO_STORAGE_LIMITS=1` also opts ordinary/operator exports into these bounds; otherwise ordinary preparation/export behavior is unchanged.

Normal completion, failure and cancellation remove only that operation's fresh disposable directory before releasing its reservation. Inference kills its private process group before cleanup. An interrupted process or failed cleanup retains the reservation across restart; startup does not guess whether a child is still using those files. Such retained reservations can block new work until the host verifies an orphan and recovers it. Recovery requires stopping that workspace and confirming its workers have ended, then inspecting the exact ledger-owned disposable directory and its reservation together. Do not delete the ledger or remove native drafts, annotations, caches or another operation's directory to recover space.

Provider temporary directories are directed into the inference worker's private `provider-scratch/` directory for cleanup, but their aggregate size is **not** covered by the serialized input/result reservation. A per-file limit does not bound the number or total size of provider files, and `TMPDIR` is not a filesystem sandbox. External decoder services, native mounts, pre-existing legacy spools, database/filesystem overhead and unrelated processes remain outside these application spool limits. Configure durable host/filesystem quotas and service resource budgets before public deployment; do not claim that these application checks alone bound the host disk or memory.

## Job admission and visitor deadlines

The local job executor accepts at most 32 unfinished submissions across the server and four per account, including both running and queued work. The account limit spans projects. A full queue returns `429` with `Retry-After: 5` before inserting a job; retrying an existing idempotency key still returns that job. Cancellation does not release a queue reservation until its actual executor item finishes or is consumed, so repeatedly cancelling and resubmitting cannot grow the executor queue without bound. Exceptions also release reservations. Restart recovery marks unfinished ledger records interrupted rather than replaying them automatically.

These are admission bounds, not round-robin scheduling, per-user storage quotas, or an inference time/memory guarantee. The worker count remains separate from the queue limits. Completed records and submitted data still need retention and storage controls.

Registration/sign-in starts a persisted absolute deadline. Logging out, refreshing, creating another token, reconnecting a desktop, or restarting the server does not reset it. Expired credentials cannot sign in again; existing usernames cannot be reused until an explicit reset removes those accounts. `GET /api/auth/session` supplies the server clock and account deadline. The main workspace, Slicer/QuPath browser wrappers, OHIF assistant panel (including its manual-editing tab), and managed CVAT page share the same countdown implementation and public-data reminder. Each polls the same account deadline; small display differences between tabs reflect request/tick timing, not different leases. Native standalone applications and externally hosted CVAT are not covered by these browser banners. OHIF/CVAT display expiry without navigating away from local drafts; they cannot submit after expiry. Authentication enforces expiry independently of the display.

## Automatically approved public signup

After the host has approved public registration and verified the HTTPS, isolation and resource boundaries, enable `MONAILABEL_DEMO_PUBLIC_REGISTER=1` alongside `MONAILABEL_DEMO_SELF_REGISTER=1`, `MONAILABEL_DEMO_CACHE_ONLY=1`, `MONAILABEL_DEMO_TRAINING_PREVIEW=1`, `MONAILABEL_DEMO_HTTP_LIMITS=1` and `MONAILABEL_DEMO_LIFECYCLE=1`. This is an explicit change from invite-only admission: anyone who reaches the signup page can create an account. No email service or manual approval is used. Existing administrator and invited accounts are preserved.

The browser uses `POST /api/auth/signup` to create an automatically approved account, then signs in. Signup does not allocate a GPU slot, start the timer, create a project or issue a session. First successful sign-in atomically checks capacity, creates one private starter project and starts the absolute deadline. If full, the account remains approved; the user signs in later without registering again. Approval does not guarantee immediate capacity. Account creation has a global ten-attempts-per-minute hash limit, a 1,000-visitor-account ceiling and the HTTPS edge's source-based authentication rate limit. Anonymous registration cannot choose roles or promote an account.

Public-signup visitors receive only Annotator and Reviewer roles, never Manager or Administrator. The authorization layer also caps their effective roles, and project creation is refused through both HTTP and assistant service paths. On first admission, a bounded background job imports one already-cached public Spleen CT into the visitor's project. The fixed `POST /api/demo-access/starter` operation accepts only an optional `example` choice: `radiology` (default), `pathology` or `endoscopy`. It never accepts a project ID, URL, import size or role override. It reuses an existing sample or matching active import, permits only one sample import at a time and bounds retries per example. It never downloads an uncached dataset. The operator must prepare the sample caches, desired models and viewers before opening signup. Visitors cannot manage memberships, providers, uploads or arbitrary dataset imports. See [Prepared visitor examples](demo-examples.md) for the QuPath, CVAT, Slicer and OHIF walkthroughs and GPT setup boundaries.

Administrators see **Team & roles → Users**, an account directory independent of project membership. It includes accounts whose visits have not started, active/expired visitors, disabled users and administrators. Its read-only `GET /api/auth/accounts` endpoint requires administrator authentication and never returns password records. Other account-management and reset endpoints remain private at the HTTPS edge. Disable `MONAILABEL_DEMO_PUBLIC_REGISTER` to stop public signup without deleting existing accounts or annotations. This prevents new accounts, not logins by existing approved visitors.

## Expiry and an explicit fresh demo

Enable `MONAILABEL_DEMO_LIFECYCLE=1` for the private Linux pilot. An independent server sweep starts every half second when the previous sweep has completed, including after a restart. It cancels the visitor's queued/running job records, revokes credentials, stops owned browser-desktop containers, and ends managed CVAT bindings. The visitor-only managed-viewer restriction is independent of this flag, but automatic resource shutdown requires the sweeper. Closing a tab is not required for expiry. Save or submit before the deadline: stopping a desktop discards unsaved native state.

Local segmentation, explicitly enabled GPT annotation, prompted inference and video tracking use fresh-interpreter subprocess groups for timed jobs. Cancellation checks poll at 100 ms while inference runs; termination kills the visitor's worker group, including nested model workers, without killing the shared coordinator or another visitor's work. This is process lifecycle containment, not a security sandbox; killing a hosted request cannot reverse an upstream charge. Use a service manager that stops the entire service control group on shutdown, including forced shutdown. CPU import/provisioning stages remain cooperatively cancelled at their progress/publication boundaries. Publishing transactions recheck the acting visitor's deadline. Live training and unapproved hosted annotation remain unavailable to timed visitors.

Access stops at the deadline; physical cleanup is asynchronous and can be delayed by an unavailable Docker/CVAT service. A failed stop retains the admission reservation and is retried. CVAT can cancel a queued video import but cannot safely interrupt a started, mutating decode through its supported API. The binding is revoked immediately; its reservation remains held until decoding completes. Likewise an already-issued coordinator request may finish, but its reply cannot execute further tools or publish after expiry. No unsupported shared-service kill is attempted. These are explicit limits, not a guarantee that every process stops in exactly one second. Universal bounded termination, import limits and public abuse prevention remain release gates.

Administrators see **Team & roles → Start a fresh demo**. Opening it obtains a preview; no accounts are removed until the administrator types `START FRESH DEMO` and submits. A changed visitor/project membership set invalidates that preview. The backend requires administrator privileges, enabled lifecycle controls, and no unfinished jobs, executing cancelled jobs, browser desktops, assistant replies or tracked CVAT preparation. A normal server restart never resets accounts.

Reset removes only demo-lease accounts, their login credentials/memberships, and projects belonging exclusively to those visitors. Administrator and ordinary accounts, mixed/shared projects, shared dataset/model caches, operator-prepared predictions and recorded training examples remain. Conversations, tool outcomes, jobs/logs and review decisions belonging to removed visits are archived as operator-only `DemoFeedback` records. Existing bounded JSONL telemetry is not cleared. `DemoVisit.id` is the unique account/visit ID; it retains username, round ID, creation/start/deadline and reset timestamps. Reusing a username creates a new visit ID and round association, so feedback is never attributed by username alone. Do not store plaintext passwords in feedback.

Reset removes visitor workspace records, not every physical byte immediately. Content-addressed artifacts are reclaimed by ordinary startup garbage collection when no retained record references them; external CVAT drafts are retained, inaccessible through removed accounts. Archive retention and backup disposal remain operator responsibilities, separate from telemetry rotation. Back up the workspace and ask for permission before executing this reset against existing visitor data; use disposable workspaces to test it.

Set `MONAILABEL_DEMO_AUDIT=1` to enable local research telemetry. A notice appears before login; the session banner shows only the deadline and public-data reminder. Events record account IDs, successful logins, HTTP mutation outcomes and errors, assistant prompts and final replies, tool names, job IDs, and semantic clicks in the workspace/browser-desktop wrapper. HTTP records use route templates, not arbitrary URLs, request bodies or headers. Records are not exposed through a visitor API. `GET /api/demo-access/audit-status` is administrator-only; the host reads JSONL files in the workspace's private `demo-audit` directory.

The telemetry writer uses one CPU thread and no GPU or external telemetry service. Its queue has 512 slots, its global intake limit is 100 events/second, individual records are capped at 16 KiB, text fields at 4,000 characters, and four rotating files at 5 MiB each. Files also rotate daily. A periodic sweep removes files whose oldest event is over seven days old. Queue overflow, rate limiting and disk errors drop events rather than block annotation; the status endpoint counts drops and write errors. This is bounded research telemetry, not a lossless security audit. Browser-originated events are explicitly untrusted and can be omitted or forged by a client.

No form values, raw keystrokes, screen recordings, images, credential configuration or arbitrary tool arguments are captured by this telemetry. Free-text redaction detects common credential patterns but cannot reliably identify all credentials or patient information. Restrict trials to public data and disclose the recording. Retention sweeps operate while telemetry is enabled and running; the host must manage retention while it is offline or disabled, and for backups. Existing application conversations, annotations and job records have their own storage lifecycle: telemetry rotation does not delete them.

Set `MONAILABEL_DEMO_CACHE_ONLY=1` to restrict the dataset-template menu to locally verified cached datasets (including associated mask archives) for all accounts. Leased visitors have this restriction even without the flag. Direct template imports also reject a cache miss before job creation, and the downloader itself refuses network access on a miss. Normal operator preparation runs without this flag and verifies pinned checksums. A cache marker is only trusted in an operator-controlled cache; visitors must not have write access to it. This flag is not a global model/download or filesystem sandbox.

## Remaining gates, in order

The training preview and offline example preparation are described in [demo training](demo-training.md). Enable the preview flag to block live training independently of the remaining admission and isolation work below.

1. Prepare and validate the intended model/viewer catalog as the host. Visitor no-download controls are enforced as described above; they do not install missing resources. Before offering a model or viewer, exercise its prepared weights, worker environment, Docker image and viewer assets with disposable inputs, and verify both successful use and refusal on a cache miss. Runtime version checks and real model smoke tests complement the lightweight catalog preflight. Cached weights do not mean all models must remain loaded in GPU memory.
2. Configure host/provider/external storage containment and validate scheduling under load. Artifact quotas, metadata allocation bounds and application-owned export/inference spools are implemented above; provider scratch, external data, native mounts and filesystem overhead remain separate. Admission, authenticated request-rate limits, transport limits, five-sample template imports and the bounded executor are not a whole-filesystem quota or a fair GPU scheduler. Start conservatively: two admitted visitors, one expensive annotation job at a time, short sampled datasets, no visitor training or fine-tuning. Measure latency and memory before raising limits. Preserve shared caches rather than duplicating the whole archive per visitor.
3. Close the remaining lifecycle limits: bound CPU/provisioning work and already-started CVAT imports, apply per-visitor storage limits and admission near expiry, and define retention for archived work/external drafts. The implemented lifecycle above covers access revocation, managed desktop shutdown, isolated local inference termination and explicit reset, but does not constitute a universal process or storage sandbox. Do not extend the private registration pilot to public access until these limits and abuse prevention pass.
4. Extend semantic event coverage to OHIF/CVAT and native viewer bridges, including acknowledgement of edits, job completion/failure and correlation of a prompt with the resulting action. The current wrapper cannot tell which Slicer/QuPath control was clicked inside a streamed desktop. Define retention for application conversations and work products as well as telemetry. Never claim every interaction was captured.
5. General multi-action viewer requests still need acknowledgement and sequencing. TotalSegmentator replacement is now one typed annotation operation rather than clear-then-infer: `all_targets=true, replace_existing=true`. No viewer deletion is sent first. The proposal replaces the draft only after successful inference and unchanged revision/draft checks. Other arbitrary action sequences are not implemented.
6. Invite a trusted reviewer over the existing private access path. Test disposable visitors with a short test-only expiry, multiple tabs, concurrent users, uncached Liver requests, queue saturation, logging failure and cleanup. Do not grant administrator or shell access just to test annotation.
7. Only then activate the external network boundary, TLS and public admission. The [HTTPS staging package](https-deployment.md) prepares a loopback-only edge and its validation/rollback procedure without publishing it. An OPNsense spare interface can provide a dedicated routed demo subnet, without moving the GPU host into a VM. Configure explicit IPv4/IPv6 policy, block home LAN and management access, prevent bypass through other host interfaces, and test from inside the viewer environment. A firewall does not isolate writable resources between visitors; desktop/process containment remains a separate requirement.

## All-structure radiology demo

In Slicer or OHIF, choose **TotalSegmentator CT**, then **Segment all 117 labels**. No single-target selection or coordinator call is required. MRI offers its own 50-structure catalog; select a modality-appropriate model. Results use the pinned fast 3 mm model. Structures outside a scan's field of view can have empty masks. Projects, submission and review support the uint8 ceiling of 255 foreground structures; this does not expand the separate learning recipe/target limits.

The equivalent chat request is `Segment this CT using TotalSegmentator CT on all labels.` For explicit replacement, use `Delete the current segmentation and run TotalSegmentator CT on all labels.` Replacement keeps saved revisions immutable and retains local work if inference fails or the source/draft changes. The ordinary all-label button preserves unrelated structures and rejects overlapping edits; it does not implicitly authorize deleting other labels. Workflow success is not clinical validation.

Slicer imports all structures into a shared multilabel grid instead of allocating a full source-volume mask per organ. Exact-grid shared layers use a single readback; independent or cropped native edits retain the geometry-aware fallback and overlap rejection. Native undo remains available.

Operators can run `uv run python scripts/demo_prepare_totalseg.py --datasets /path/to/cached/datasets --models /path/to/cached/models --output /path/to/prepared-predictions` before a demo. This processes image members of already cached Spleen, Lung and Liver archives sequentially, not their reference masks or MRI archives. It checks existing pinned weights without downloading, records exact model/geometry/checksum evidence, and can resume verified outputs. `--idle-database /path/to/workspace/monailabel.sqlite3` reads only aggregate job/desktop state and waits between scans while the application is busy. Resource containment should also be applied by the host; the command itself is not a GPU scheduler.

Set `MONAILABEL_TOTALSEG_PREDICTIONS=/path/to/prepared-predictions` to reuse these read-only base predictions. Cache identity includes image values, source geometry, provider, weights, version and configuration. Project label IDs are remapped privately at each request; visitor corrections never update the cache. Derived models bypass base predictions. Missing entries run normal inference; invalid entries fail rather than silently supply mismatched results. The provider logs reuse. Prepared results demonstrate viewer workflows, not the elapsed time of fresh inference. Some archive volumes exceed the application's upload/voxel limits and cannot be imported into the demo even if their offline prediction was prepared.
